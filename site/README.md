# TEF Notes site

The marketing page: Vite, React 19, Tailwind 4. Its colours and fonts come from the app (`../packages/core/src/theme.ts`, `../assets/fonts`), so build with the repo checked out whole.

- `bun install && bun run dev` to work on it, `bun run build` for static files in `dist/`, `bun run preview` to serve them.
- No screenshots: every screen in the frames is drawn in React and CSS in `src/components/mock/` (one file per screen, shared pieces in `parts.tsx`), at a fixed design size (1440 web, 390 phone) scaled to its frame by `screen.tsx`. The phone screens are the installed web app at phone width (`web/src/components/`: `tab-bar.tsx`, `home.tsx`, `days.tsx`, `task-list.tsx`, `search-drawer.tsx`, `share-page.tsx`, `assistant/`). A `Peek` (`ui.tsx`) shows one region of a screen (`crop`, in design pixels) or a panel drawn at its own size (the assistant's dock, the clipper's popup), so a section shows the one detail it is about rather than a whole window and a whole phone. Demo content is fictional; colours and icons are the page's tokens and lucide's.
- `src/look.css` is the look a drawn screen needs anywhere (the faces, the colour names over `--tf-*`, the note colours, the drawn pictures, the grid); `src/index.css` imports it and adds the page's own. `washes.ts` is the site's tints of a theme, read at build for the page's CSS and at runtime by `scoped` (`src/components/ui.tsx`), which sets any theme on one element.
- The promo film (`../video`) draws these screens: it imports `src/components/mock/`, `ui.tsx` and `look.css`. A mock's props (`ClipperPopup`'s `note`, `PhoneTasks`' `tasks`, `AskDock`'s `turn` and `draft`) and its `data-tap` marks are how a scene drives it; keep them when a mock changes, and run the film's stills (`../video/README.md`). The page shows the film in its `#film` section (`src/components/Film.tsx`) only in a build that has `public/film.mp4`: the Pages workflow renders it there, nothing commits it, and a build without one (the Dockerfile's, a local one) has no such section.
- Deploy `dist/` to any static host, or `docker build -f site/Dockerfile -t tefnotes-site .` **from the repo root** (the build context must include `packages/core` and `assets`) and serve port 80.
- The repository address (`REPO`, which the GitHub and clone links derive from) lives in `src/lib.ts`.
- GitHub Pages: `.github/workflows/pages.yml` builds it on a push to `main` that touches `site/`, `video/`, `packages/core/` or `assets/`, and publishes `dist/` at `https://spyrosbazios.github.io/tef-notes/` (Settings > Pages > Source: GitHub Actions). That build sets `SITE_BASE=/tef-notes/`; `vite.config.ts` reads it as `base` and defaults to `/`, so the Dockerfile and any root-served host are unchanged. Build with it to check: `SITE_BASE=/tef-notes/ bun run build`.
- A path the page names itself goes through Vite's `base` (`%BASE_URL%` in `index.html`, `import.meta.env.BASE_URL` in code), never a bare `/...`. There is one page and no router, so no SPA fallback.
