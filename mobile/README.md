# TEF Notes for Android

<!-- reviewed: 2026-11-07 -->

The TEF Notes phone app: an Android-only, offline-first client for your own TEF Notes server. Notes and tasks
live in a local SQLite cache and sync with the server (`../server/`) in both directions, live while the app is open.
With no server set it still works as a notes and to-do app on the phone alone.

## Features

- **Home**: the day at a glance, as the web's: the days, a task box (Today, Inbox, Upcoming), then every note as tiles, filtered by tag, sorted or grouped, with a + beside Notes for a new one; the lens in the header. Tasks, Ask and Settings are tabs; search is a drawer opened from the header.
- **Notes**: markdown notes with tags, colours, pinning, photos, PDFs and link previews. A rich editor, full-text search
  and a merge when the same note changed on the phone and elsewhere.
- **Tasks**: Inbox, Today, Upcoming and Logbook, with deadlines, repeats, checklists and reminders (local
  notifications).
- **The assistant**: a chat with the agent that runs on your server, a button away on every screen as a sheet over it; it can open
  the notes, tasks and views it talks about. It reads, writes and resurfaces notes and tasks, asking before
  it writes unless you turn that off. Replies keep streaming with the app in the background.
- **Share to TEF Notes**: Android's Share sheet files a link, text, a photo or a PDF into a note or task, or hands it to the agent.
- **Home and lock screen widgets**: Today (tick tasks off) and a quick Ask / new note.
- **Voice dictation** into any composer, on the device, with no speech service.
- Sixteen themes, from OLED black to sepia paper, with Catppuccin, Nord, Rosé Pine, Tokyo Night, Gruvbox and Solarized among them.

## Requirements

- Node.js, and pnpm 11 through `npx pnpm@11` (the lockfile is pnpm 11's; pnpm 10 rewrites it and then refuses
  `--frozen-lockfile`).
- [bun](https://bun.sh): the scripts that generate the app's pages and icons run on it.
- JDK 17 or newer.
- The Android SDK, with `ANDROID_HOME` pointing at it (your Android SDK directory).
- An arm64 Android device (USB debugging on) or an arm64 emulator. The build targets `arm64-v8a` only
  (`app.config.ts`, `expo-build-properties`).

## Build

`android/` is generated by `npx expo prebuild` and is not committed. Native behaviour is set in `app.config.ts` and the
config plugins in `plugins/`, never by editing `android/`. The Android app id is `app.tefnotes.mobile`; if you fork the app,
change `android.package` in `app.config.ts`.

Run all of it from this directory.

### Development

```sh
npx pnpm@11 install
(cd ../web && bun install)     # the generated pages below are built from web/
npx pnpm@11 android            # builds the pages, then a dev build on the connected device, with hot reload
```

`pnpm android` and `pnpm start` run the `pages` script first. Running `npx expo run:android` on its own does not, and
fails on a fresh checkout for want of the pages.

### Release APK

```sh
npx pnpm@11 pages
npx expo prebuild
cd android && ./gradlew assembleRelease
adb install -r app/build/outputs/apk/release/app-release.apk
```

The release APK is signed with the generated project's debug keystore unless `TEF_NOTES_KEYSTORE` names a keystore file
(`plugins/release-signing.js`, which also reads `TEF_NOTES_KEYSTORE_PASSWORD`, `TEF_NOTES_KEY_ALIAS` and
`TEF_NOTES_KEY_PASSWORD`). The debug key is fine for sideloading to your own phone; the release workflow signs with its own.
The app's `version` and `android.versionCode` come from the git tag ([`../CONTRIBUTING.md`](../CONTRIBUTING.md#versioning)), not from `package.json`.

### Generated files

Four files are generated and gitignored. `typecheck`, `android` and `start` build them first (the `pages` script, which
needs bun and `web/`'s dependencies); a plain `tsc` or `expo run:android` does not.

| File | Made by | From |
|---|---|---|
| `src/ui/editor-html.ts` | `web/` `bun run build:editor` | the note editor, a ProseMirror page the app shows in a WebView (about 930 KB with its fonts inlined) |
| `src/ui/pdf-html.ts` | `web/` `bun run build:pdf` | the PDF viewer, a pdf.js page in a WebView (about 2 MB) |
| `src/theme.css` | `scripts/theme-css.ts` | the palettes in `packages/core/src/theme.ts`, one Uniwind theme each |
| `src/uniwind-types.d.ts` | `uniwind generate-artifacts` (in `typecheck`, and Metro) | `src/global.css` and the theme names |

## Connect to a server

The phone needs a running TEF Notes server (see `../server/`). In the app, open Settings, then Server, and type its address
(`https://host:port`). The address is the only setting kept in SecureStore (Android Keystore); nothing secret is in the
bundle or the repo.

- **There is no sign-in.** Anyone who can reach the server can read, write and delete every note, so keep it on a private
  network such as a VPN or a Tailscale tailnet, and never expose it to the internet.
- The phone holds no model or search key. The AI keys belong to the server, and the agent runs there.
- With no address set, or no connection, everything keeps working on the phone. Edits are sent when the server is next reachable.

The note format, the revision (`rev`) contract the server enforces on every write and the agent's design are described
in [`../ARCHITECTURE.md`](../ARCHITECTURE.md).

## Android features

This is why the app is Android-only:

- Widgets (`react-native-android-widget`): `TodayWidget` and `QuickWidget`, on the home screen and the lock screen,
  redrawn every 30 minutes.
- A foreground service keeps a streaming reply alive in the background.
- On Android 16 the reply in flight shows as a Live Update; below that it is an ordinary notification.
- Share-to-app through Android's Share sheet.
- Task reminders as local notifications, scheduled on every save and sync.

## Checks

```sh
npx pnpm@11 typecheck    # builds the generated files, then tsc --noEmit
npx pnpm@11 lint         # expo lint
npx pnpm@11 test         # vitest: the local database, sync and the stores
```

Tests of the shared code are in `../packages/core` (`cd ../packages/core && bun test`).

## Layout

- `src/app/`: Expo Router screens (tabs: Home, Tasks, Ask, Settings), plus note, task, chats, settings, share, PDF and photo viewer.
- `src/store/`: zustand stores, the SQLite cache and the sync engine, the realtime feed.
- `src/ui/`: shared components; `src/ui/ds/` is the design system, `src/ui/chat/` the chat's pieces; the assistant is the Ask tab (`src/app/(tabs)/ask.tsx`).
- `src/widget/`: the home and lock screen widgets.
- `src/agent/`: the background service for replies.
- `plugins/`: Expo config plugins for the native pieces (`background-reply`, `live-update`, `task-alarms`).
- `../packages/core/`: `@tefnotes/core`, the pure TypeScript shared with the web app, the CLI and the extension (note format,
  merge, tasks, theme). Imported here as `@/core/*`.

Working notes for contributors and coding agents are in [`AGENTS.md`](AGENTS.md).
